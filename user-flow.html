Critical journeys

Permission should feel invisible until it needs explanation.

ACCESS optimizes routine entry for speed while keeping denial, expiry, offboarding and emergency scenarios explicit. The same identity model drives employees, visitors, contractors and admins.

Hero flowEmployee arrival
Exception focusDenied · expired · revoked
Admin flowLockdown + recovery
04.01

Employee arrival

Fast happy path with visible trust checkpoints.

01Approach reader

Wallet/Watch credential ready.

02Detect intent

NFC tap or BLE wave.

03Validate policy

Identity + zone + schedule.

04Unlock

Green confirmation + relay event.

Failure branch: invalid zone, revoked credential or schedule mismatch returns an explicit denial reason and recovery path rather than a generic “Access denied”.
04.02

Visitor journey

Hospitality and security need to coexist across invitation, arrival and expiry.

PRE-VISIT

Host pre-registers visitor

Name, company, destination, time window and policy requirements are defined.

VERIFY

Visitor completes ID / NDA

Browser flow creates a temporary credential only after required steps succeed.

ARRIVAL

Dynamic QR accepted

Kiosk/reader checks visit window, destination and revocation status.

HANDOFF

Host receives notification

Slack/Teams ping confirms arrival without making the visitor wait at reception.

EXPIRY

Credential automatically invalidates

Door access ends with the visit window; audit trail remains.

04.04

Offboarding flow

Digital identity changes must propagate into physical access safely.

HRIS

Employee marked terminated

Workday/HR source sends lifecycle change.

SCIM

Directory revokes access role

ACCESS receives identity update and invalidates credentials.

READER

Former credential denied

Reader shows revoked state with no misleading retry loop.

AUDIT

Revocation remains traceable

Time, source, identity and affected sites are recorded.

04.05

Emergency lockdown

High-consequence admin action requires scope confirmation, system acknowledgment and degraded-mode handling.

TRIGGER

Admin chooses site lockdown

UI states affected site, doors and life-safety exclusions before commit.

CONFIRM

Destructive confirmation

Explicit second step prevents accidental activation.

PROPAGATE

Readers acknowledge command

Exterior and restricted doors move to lockdown state.

EXCEPTION

Unconfirmed reader isolated

Global state stays active while security receives the exact device requiring manual response.

RECOVERY

Authorized release

Lockdown ends through a separately permissioned action and records a complete audit event.

04.06

Validation plan

These are target validation tasks, not claimed measured outcomes.

Task 01

Employee entry

Can a user understand successful vs denied entry without relying on LED color?

Task 02

Visitor recovery

Can a visitor with an expired pass identify the next safe action without staff intervention?

Task 03

Admin emergency

Can security scope, activate and verify lockdown without ambiguity about unresponsive doors?
