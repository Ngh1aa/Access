05.02

Core review scenarios

A reviewer can understand the prototype fastest by following these scenarios.

01 · EMPLOYEE

Wallet credential → smart reader → granted entry

Tests frictionless routine access and non-color-dependent feedback.

02 · VISITOR

Invitation → verification → temporary QR → auto-expiry

Tests hospitality/security balance and host handoff.

03 · OFFBOARD

HRIS change → credential revocation → denied access

Tests identity lifecycle and physical enforcement.

04 · EMERGENCY

Lockdown → reader acknowledgments → degraded-device handling

Tests high-consequence admin clarity.

05.03

Fidelity boundaries

What the prototype demonstrates — and what it does not claim.

Implemented

Experience + interaction model

Responsive HTML/CSS, product storytelling, device/credential simulations, multi-page navigation, accessibility targets and scenario-driven interaction.

Simulated

Hardware + enterprise infrastructure

NFC/BLE exchanges, relay behavior, SCIM timing, lock hardware, Apple Wallet issuance and enterprise audit backends are represented for UX evaluation, not connected to production systems.

05.04

Critique checklist

Use these questions when reviewing the work as a product-design artifact.

COMPREHENSION

Is the permission model obvious?

People → identity → credential → building → door/floor → permission.

SAFETY

Can users distinguish granted, denied, expired and lockdown without color?

Labels, status copy and spatial feedback should all agree.

RECOVERY

Do broken physical states lead somewhere useful?

Offline readers, expired passes and unconfirmed lockdown devices need explicit next actions.

RESPONSIVE

Does spatial storytelling survive smaller viewports?

Mobile should simplify composition without flattening every story into generic cards.
